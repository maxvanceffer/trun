## Question

Как ведут себя фильтры Console в DetailPage (зона из скриншота над CONSOLE): какие контролы, какая логика, что происходит с непарсящимися строками?

Разобрать с человеком (grilling + domain-modeling, breadth-first запрещён — только эта ветка): текстовый запрос vs level vs channel/target (Application, DOCTRI/DOCTRINE, Web Server, SERVER…) vs временной диапазон; AND/OR комбинация; hide-non-matching vs highlight; счётчики совпадений; пустое состояние («фильтрам нечего показать, потому что строка не парсится»); поведение при живом потоке (автоскролл, пауза); сброс/состояния по умолчанию; доступность без парсинга (plain-text всегда работает?). Словарь каналов заранее неизвестен — фильтры должны строиться из наблюдаемых значений потока. Зафиксировать решение-таблицу, не код.

## Answer

Grilling, 2 раунда (2026-09-16). Итоговая таблица решений:

1. Измерения — 4 с AND: текстовый запрос (substring, case-insensitive, без regex) + уровень (из потока) + канал (из потока) + время (пресеты 5/10/30 мин + всё время; сентinel all-time вида null/-1/Any — на spec/реализацию). Пустой фильтр = выключен.
2. GUI: hide несовпавших + счётчик «показано X из Y» + пустое состояние с честной причиной. Highlight-версию отвергли.
3. Непарсящиеся строки: участвуют только в текстовом поиске; под активным level/channel скрыты; пустое состояние сообщает, сколько строк скрыто как нераспознанные.
4. Живой поток: фильтры применяются на лету, автоскролл как сейчас. Паузу — НЕ делаем (отвергнута человеком как бессмысленная); счётчики всегда живые.
5. Жирные строки: в UI обрезка (~500 символов, точный лимит на spec) с expand; полная строка остаётся в буфере/копировании. В MCP — полные строки сразу.
6. Селекторы level/channel: мультиселект-чипсы из наблюдаемых значений текущей Console history; словари нигде не хардкодим. Термин-карта: «канал» фильтра = LogModel.target (слой 1) ∪ layer-2 channel.
7. Дефолт: все фильтры выключены (лог как сейчас); кнопка «очистить всё»; выбор живёт пока открыта Detail page (session-only). Персистентность per Command — сознательно отложена, пересмотрим после v1.
8. Требование к MCP (передано в тикет MCP-поиска): накопленные списки level/channel должны быть доступны ИИ — иначе «дай ошибку DOCTRINE» не сформулировать.
